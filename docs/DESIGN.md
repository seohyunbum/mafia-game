# 마피아 게임 — 설계 정본 (초안 v0.1)

> 최초 작성 2026-07-27. 사용자 구술 설계 1차 입력 반영.
> **이 문서가 규칙의 정본이다.** 코드·데이터가 이 문서와 어긋나면 문서를 먼저 고친다.

## 0. 표기 규칙

| 표기 | 뜻 |
|---|---|
| ✅ | **확정** — 사용자가 직접 말한 규칙. 임의로 바꾸지 않는다. |
| 🟡 | **해석** — 사용자 발언을 내가 해석해 채운 부분. 다음 입력에서 확인받아야 한다. |
| ⬜ | **미정** — 후속 설계 입력 대기. 코드에서 `null`/미구현으로 둔다. |

밸런스 수치는 코드에 하드코딩하지 않고 [`data/`](../data/) JSON에 둔다.
확정되지 않은 수치는 JSON에서도 `null`로 남긴다 (임의값으로 채워 확정처럼 보이게 하지 않는다).

## 1. 게임 개요

역할 기반 심리 추리 게임. 밤에는 마피아가 사람을 죽이고, 낮에는 살아있는 사람들이
토론·투표로 마피아를 색출한다. 여기에 두 가지 축이 추가된다.

1. **변신** — 마피아가 낮에 시민 캐릭터의 외형을 뒤집어써서 투표를 엉뚱한 곳으로 유도한다.
2. **3파전** — 시민팀 / 마피아팀 / **교주팀**이 각자 승리 조건을 갖는다.

전원 HP 2라서 **한 번 지목당해도 즉사하지 않는다.** 이게 이 게임의 핵심 감각이다 —
"틀린 투표"가 한 번은 용서되지만, 두 번째는 사람을 죽인다.

---

## 2. 게임 모드 (실행 직후 선택) ✅

실행하면 먼저 모드를 고른다.

| 모드 | 내용 |
|---|---|
| **솔로** | 혼자 참가. 자기 팀이 이기면 승리. |
| **듀오** | ✅ 둘이 **같이 편먹고** 한다. 두 사람이 한 팀으로 묶여 같은 진영이 되고, 승패를 공유한다. |

🟡 듀오 세부 해석 (확인 필요):
- 듀오 짝은 서로의 정체를 **처음부터 알고 시작**한다. (모르면 "같이 편먹는다"는 말이 성립하지 않음)
- 짝의 진영은 같다. 둘 다 마피아, 또는 둘 다 시민.
- 짝 중 한 명이 죽어도 남은 한 명이 진영 승리 조건을 달성하면 팀 승리.

⬜ 미정: 듀오가 로컬 2인 플레이인지 / 온라인 매칭인지 / 한 명 + AI 파트너인지 (§10 Q13)

## 3. 진영과 승리 조건

| 진영 | 구성 | 승리 조건 |
|---|---|---|
| **시민팀** | 일반 시민 + 특수 직업 시민들 ⬜ | ⬜ 미정 (통상 "마피아팀·교주팀 전멸") |
| **마피아팀** | 일반 마피아, 폭탄마 ⬜ | ✅ **시민팀과 교주팀 전원이 죽으면 승리** |
| **교주팀** | ⬜ 미정 | ⬜ 미정 |

✅ 확정된 것은 마피아팀 승리 조건 하나뿐이다. 교주팀은 이름과 "마피아의 제거 대상"이라는
사실만 확정. 정체·인원·능력·승리 조건은 후속 입력 대기 (§10 Q11).

🟡 승리 판정 시점 해석: 매 페이즈(밤 결과 적용 후 / 낮 처형 결과 적용 후)마다 즉시 판정.

## 4. 캐릭터 공통 규칙

### 4.1 체력 ✅

- **모든 캐릭터의 최초 HP = 2.** 역할·진영 무관.
- HP 0 → 사망.

### 4.2 배역 배정 ✅

- 모드를 선택하고 **시작하자마자** 마피아인지 시민인지(=진영과 역할이) 즉시 결정된다.
  로비에서 고르는 게 아니고, 게임 시작 시 무작위 배정 후 본인에게만 통보.

### 4.3 캐릭터 vs 플레이어 🟡

변신 규칙이 "특정 **시민 캐릭터**로 변신"이라고 말하므로, 캐릭터는 단순한 슬롯이 아니라
**이름·외형이 있는 식별 가능한 개체**로 본다.

- `Character` = 게임에 등장하는 인물 (이름·외형·HP·생존 여부)
- `Role` = 그 인물이 맡은 직업 (일반 마피아, 폭탄마, 시민, …)
- `Actor` = 그 인물을 조종하는 주체 (사람 플레이어 / AI)

⬜ 캐릭터 목록(이름·외형 세트)이 고정 로스터인지, 매 게임 생성인지 미정 (§10 Q9).

## 5. 역할

### 5.1 일반 마피아 (마피아팀) — 부분 확정

**밤 행동 ✅**
- 한 명을 지목해 **죽인다.**
- 🟡 "죽인다"는 HP 감소가 아니라 **즉사**로 해석한다 (HP 2여도 밤 살해는 확정 사망).
  → 후속 확인 필요 (§10 Q2). 만약 밤 살해가 -1이라면 게임 길이가 크게 변한다.

**아침 스킬: 변신 ✅**
- 아침이 되면 **변신**을 쓸 수 있다 (선택적 사용).
- 사용하면 **랜덤으로 특정 시민 캐릭터로 변신**한다. 대상은 마피아가 고르는 게 아니라 무작위.
- 변신한 상태에서 **사람들이 나를 지목(투표)하면, 그 원본 시민 캐릭터의 HP가 1 깎인다.**
  - 🟡 핵심 해석: 피해를 받는 것은 **내가 흉내낸 그 원본 시민**이다. 마피아 본인은 무피해.
    즉 변신은 "투표를 흡수해서 애먼 시민을 대신 때리게 만드는" 기술이다.
    (사용자 발언 "내 원본 시민 케릭터의 피가 1 깎임" 의 "내 원본"을 *내가 변신한 원본* 으로 읽음)
  - ⚠ 반대 해석 가능성: "마피아 본인의 진짜 몸이 1 깎인다" — 이러면 변신은 은신 대가로
    리스크를 지는 기술이 된다. **둘 중 어느 쪽인지 확인 필요 (§10 Q1).** 게임의 성격이
    정반대로 갈리는 가장 중요한 미확정 항목이다.

**미정 ⬜**
- 변신 지속 기간 (그 날 하루? 다음 변신까지 유지? 해제 가능?) — Q5
- 변신 사실이 다른 사람에게 보이는지 (같은 얼굴이 2명 되면 즉시 들킴) — Q4
- 죽은 시민으로도 변신 가능한지, 중복 변신 허용인지 — Q6
- 변신 중 밤 살해 가능한지 — Q7
- 여러 마피아가 있을 때 밤 살해 지목을 어떻게 합치는지 (합의? 각자 1킬?) — Q10

### 5.2 폭탄마 (마피아팀) ⬜

사용자가 이름만 주고 상세는 다음 입력으로 넘김. **추측으로 채우지 않는다.**
현재 확정: 소속은 **마피아편**.

기록해 둘 설계 질문: 터지는 조건(사망 시? 지목 시? 능동 설치?), 피해 범위(단일/광역),
자기 팀 피해 여부, HP 2 체계에서 피해량.

### 5.3 시민팀 직업 ⬜

일반 시민 외 특수 직업(의사·경찰류) 존재 여부 미정.

### 5.4 교주팀 ⬜

이름과 "마피아의 제거 대상"만 확정. 능력·인원·포교 여부·승리 조건 전부 미정.

## 6. 턴 구조 (초안 🟡)

확정된 건 "밤에 죽인다"와 "아침에 변신한다" 두 개의 시점이다. 거기서 최소 루프를 세운다.

```
[게임 시작]
  모드 선택(솔로/듀오) → 역할 즉시 배정 → 본인에게 통보
     │
     ▼
┌─ Night ─────────── 마피아: 살해 대상 지목. (기타 밤 능력 ⬜)
│     ▼
├─ Dawn ──────────── 밤 결과 공개. 승리 판정.
│     ▼
├─ Morning ───────── 마피아: 변신 사용 여부 결정 → 랜덤 시민으로 변신.
│     ▼
├─ Day ───────────── 토론. 이어서 투표로 한 명 지목.
│     ▼
└─ Dusk ─────────── 지목 결과 적용:
        · 지목 대상이 변신한 마피아면 → 원본 시민 HP -1 🟡
        · 그 외 → ⬜ 지목의 효과 미정 (처형=즉사? HP -1?) — Q3
      승리 판정 → 남으면 Night 로
```

⬜ 첫 턴이 밤부터인지 낮부터인지 미정.

## 7. 데이터 모델 (초안)

TypeScript 타입으로 스케치한다. 확정 안 된 필드는 주석으로 표시.

```ts
type Faction = 'citizen' | 'mafia' | 'cult';

type RoleId =
  | 'citizen'        // 일반 시민
  | 'mafia'          // 일반 마피아
  | 'bomber'         // 폭탄마 (마피아팀) — 능력 미정
  /* | 'cultist' … 교주팀 역할 미정 */;

interface Character {
  id: string;
  name: string;          // 식별 가능한 인물 이름
  roleId: RoleId;
  faction: Faction;
  hp: number;            // 시작값 2 (모든 캐릭터 공통, 확정)
  alive: boolean;
  /** 변신 중이면 흉내내고 있는 캐릭터 id. 아니면 null */
  disguisedAs: string | null;
  /** 변신이 풀리는 시점 — 지속 규칙 미정이라 아직 사용 안 함 */
  disguiseExpiresAtDay: number | null;
}

type Phase = 'night' | 'dawn' | 'morning' | 'day' | 'dusk';

interface GameState {
  mode: 'solo' | 'duo';
  /** 듀오일 때 한 편인 캐릭터 id 쌍 */
  duoTeam: [string, string] | null;
  day: number;
  phase: Phase;
  characters: Character[];
  /** 이번 밤 마피아의 살해 지목 */
  nightKillTarget: string | null;
  /** 이번 낮 투표: 투표자 id → 지목 대상 id */
  votes: Record<string, string>;
  winner: Faction | null;
}
```

### 7.1 변신 지목 해소 규칙 (의사코드 🟡)

```
resolveVote(targetId):
  target = character(targetId)
  if target.disguisedAs != null:        # 변신한 마피아를 찍었다
     victim = character(target.disguisedAs)   # 피해는 원본 시민에게
     victim.hp -= 1
  else:
     applyVoteResult(target)            # ⬜ 규칙 미정 (Q3)
  killIfZero()
```

## 8. 아키텍처 방침 (제안)

1. **순수 규칙 코어를 먼저 만든다.** UI·엔진 의존 0. 입력 = `GameState` + 행동, 출력 = 새 `GameState`.
   추리 게임은 규칙 상호작용에서 버그가 나므로, 화면 없이 테스트로 규칙을 굳히는 게 싸다.
2. **밸런스 수치는 전부 `data/*.json`.** 코어는 JSON을 읽어 동작한다.
3. **AI 플레이어는 코어 위의 별도 모듈.** 솔로 모드에는 NPC가 필요하다 (§10 Q13).
4. UI는 마지막에 얇게 붙인다.

⬜ 기술 스택 제안 (확정 대기, §10 Q14): TypeScript + Vitest 로 코어, 이후 브라우저 UI(Vite).
   `blaster` 저장소와 같은 툴체인이라 재사용이 쉽다. 콘솔 CLI로 먼저 굴려보는 것도 가능.

## 10. 미해결 질문 — 다음 설계 입력 때 답변 필요

우선순위 순. **Q1~Q3은 코어 규칙을 좌우하므로 코드 착수 전에 답이 필요하다.**

| # | 질문 | 왜 중요한가 |
|---|---|---|
| **Q1** | 변신한 마피아를 지목했을 때 HP -1 을 받는 건 **흉내낸 원본 시민**인가, **마피아 본인**인가? | 변신이 "시민 죽이는 공격기"냐 "리스크 있는 은신기"냐가 갈린다 |
| **Q2** | 밤 살해는 **즉사**인가 **HP -1**인가? (전원 HP 2인데) | 게임 길이와 마피아 강도가 2배 차이 |
| **Q3** | 낮 투표로 지목된 사람은 어떻게 되는가? 즉시 처형(사망)인가, HP -1인가? 최다득표 1명만인가? | 시민팀의 유일한 공격 수단 |
| **Q4** | 변신은 남들에게 보이는가? 같은 캐릭터가 2명이 되면 바로 들키는가? | 변신 스킬이 실제로 통하는지 |
| **Q5** | 변신 지속 기간은? 하루? 해제/재변신 가능? | 상태 관리 |
| **Q6** | 이미 죽은 시민으로 변신 가능? 다른 마피아와 같은 대상으로 중복 변신 가능? | 예외 처리 |
| **Q7** | 변신 중에도 밤 살해가 가능한가? 제약이 붙는가? | 능력 조합 |
| **Q8** | 변신 지목으로 원본 시민이 죽으면, 그 얼굴로 변신 중인 마피아는 어떻게 되는가? | 상태 정합성 |
| **Q9** | 캐릭터 로스터(이름·외형)는 고정인가? 총 몇 명인가? | 변신 대상 풀 |
| **Q10** | 총 인원과 진영 비율은? 마피아 여럿이면 밤 살해 지목은 합의인가 각자 1킬인가? | 밸런스 기반 |
| **Q11** | **교주팀**의 정체·능력·인원·승리 조건 | 3파전의 한 축이 비어 있다 |
| **Q12** | **폭탄마**의 능력 상세 (터지는 조건·범위·피해량·아군 피해) | 확정된 역할 중 유일하게 내용 공백 |
| **Q13** | 솔로는 AI와 하는가? 듀오는 로컬 2인/온라인/AI 파트너 중 무엇인가? | AI 필요 여부 = 작업량 최대 변수 |
| **Q14** | 플랫폼: 브라우저 웹 / PC 실행본 / 콘솔 텍스트? | 스택 확정 |
